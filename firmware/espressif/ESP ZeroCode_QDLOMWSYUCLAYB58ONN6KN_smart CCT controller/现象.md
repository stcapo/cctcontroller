GPIO4/5、4000 Hz、色温范围、其它项都相同。界面上像是复制出来的，新建时 Temperature mode 被默认成了另一个值。

temperature_mode: 1 是双路 MOSFET 的冷暖软件混光，关灯两路都灭，色温互补。
temperature_mode: 0 是硬件 CCT/Brightness：关灯只关亮度脚，色温脚保持上次占空比。这就是你现在看到的现象。

所以不是第二版 固件 突然不会 PWM，也不是「必须用新 product 才能配网」。是新下载的 V4 固件把模式烧成了 0。

### 直接来自初版 V4 工厂 BIN 的参数

文件：`firmware/espressif/ESP ZeroCode_V4J7LD5NCCNYVB2BZXPAES_smart CCT controller2/Devices/1/fctry.bin`

```json
{
  "pwm_hz": 4000,
  "temperature_mode": 0,
  "gpio_cold_or_cct": 5,
  "gpio_warm_or_brightness": 4
}
```

配置 CRC 已核对。配套主固件解析代码表明模式 0 启用硬件 CCT。此模式下 GPIO5 承载色温比例，GPIO4 承载总亮度；它们不是可直接解释为冷白、暖白占空比的两个输出。所有配置判断以 BIN 为准。

乐鑫同类 lightbulb 驱动的硬件 CCT 分支分别输出色温比例和亮度，关灯时仅关闭亮度通道、保留色温通道；软件冷暖混光分支则让两路同时受亮度控制。参考：[官方驱动源码](https://github.com/espressif/esp-iot-solution/blob/release/v2.0/components/led/lightbulb_driver/src/lightbulb.c)。本地保留了参考源码及当前固件模式解析的反汇编证据。

### 修订推断：模式不匹配，加上实际颜色映射可能与图纸相反

在“板上确实加载初版 V4、两路为图纸所示的高电平导通直驱结构”的前提下，最暖端色温脚接近 0、亮度脚为高输出；此时只亮冷白，提示 GPIO4 很可能实际驱动冷白。因此 GPIO5 的色温输出很可能实际驱动暖白。这是功能现象推断，尚未通过连通性或示波器确认；原因可能是灯带接线、端子标识或 PCB 与图纸的差异，不能直接认定是哪一处接反。

若上述映射成立，三种表现可解释为：

| 操作 | GPIO4：亮度信号 | GPIO5：色温信号 | 对当前灯带的预测 |
|---|---|---|---|
| 最暖、亮度最高 | 高输出 | 接近 0 | 只亮冷白，符合实测 |
| 最冷、亮度最高 | 高输出 | 高输出 | 冷白保持亮，暖白也亮，与用户补充确认相符 |
| 从非最暖状态关灯 | 降为 0 | 保留此前色温输出 | 冷白灭、暖白可能仍亮，符合关灯后暖白残留的表现 |
| 先开灯调到最暖，等待稳定后再关灯 | 降为 0 | 此前已接近 0 | 预测两路都灭，这是下一步区分实验 |

这里“高输出”和“接近 0”是理论输出方向，并非实测占空比。

用户确认最冷时两路都亮后，同一个“GPIO4 实际驱动冷白、GPIO5 实际驱动暖白，模式 0 分别输出亮度和色温”的模型能够解释本次三种现象。由于尚未直接读取板上配置和测量 GPIO，此模型仍是证据支持的推断。

本次暖白能够点亮并变亮，使“暖白回路完全无法导通/灯带暖白永久损坏”作为统一解释的可能性降低；尚不能排除间歇接触、串扰或其他硬件问题。

### 与前一次 QD swap 实测的矛盾

前一次用户确认烧入 QD 主固件 + swap 工厂配置，能控制但暖白不亮。swap BIN 实际为模式 1、Cold=GPIO4、Warm=GPIO5。若当前推断的实物映射成立，这组参数本应同时满足冷暖方向与双路关灯要求；因此不能声称仅靠本次推断就解释了先前 swap 的全部异常。

先前“原始 QD 方向正确”的建议依据图纸，应降为历史回退基准，不能覆盖本次实物证据。模式必须使用 1；GPIO 的冷暖分配需要按实测确定，而不是继续仅按图纸选版本。

下一步优先保留当前 V4 做两个观察：

1. 开灯、最冷时，将亮度从 100% 降到 20%。若冷白随亮度变化，而暖白基本不变，支持 GPIO4→冷白、GPIO5→暖白的推断。
2. 分别在“先开灯设最暖”和“先开灯设最冷”后等待至少 2 秒再关灯。该模型预测前者两路灭，后者剩暖白。不要只在关灯状态调整色温：配置 `disable_auto_on=true`，关灯时修改设置不保证立即更新输出。

然后读取一次设备 Product Config 或读回 `0x1F2000`、长度 `0x6000` 的 fctry 分区，核对实际烧录内容。若以后试模式 1，必须同步记录本次文件名/哈希、GPIO4/5 实测和灯带颜色，避免再次仅靠文件夹名称追忆版本。所有后续文件修改和烧录应围绕已验证的当前状态进行。
