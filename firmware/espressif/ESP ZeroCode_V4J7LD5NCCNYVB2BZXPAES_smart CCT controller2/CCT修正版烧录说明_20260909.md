# CCT 修正版烧录说明（2026-09-09）

本文件对应用户当前初版 V4 设备的修正版工厂配置。根据用户实际观察并基本确认的 GPIO4→冷白、GPIO5→暖白关系，改用软件冷暖混光，使亮度、色温与两路灯带输出匹配。

## 使用这个文件

```text
Devices/1/fctry_cct_fixed_gpio4_cold_gpio5_warm.bin
```

以本目录原始 `Devices/1/fctry.bin` 为基础，只改变下面三个配置字段及相应 NVS CRC：

| 字段 | 初版 V4 | 本次修正版 |
|---|---:|---:|
| temperature_mode | 0（硬件色温/亮度信号） | 1（软件冷暖混光） |
| gpio_cold_or_cct | 5 | 4 |
| gpio_warm_or_brightness | 4 | 5 |

PWM 为 4000 Hz，色温范围 2200–7000 K，渐变时间 800 ms。当前 V4 的设备身份、配网数据和其他配置字节全部保留，继续配套使用本目录已有证书和二维码。

文件大小：24576 字节（0x6000）。SHA-256：

```text
e107197a47c99e1cae74386756dc8e6c71fb649a5b55ee891019b64cc9c68ea3
```

## 烧录

只更新地址 `0x1F2000` 的工厂分区。当前已经运行初版 V4 时，不需要重烧 `all_products_merged.bin` 或 `esp_secure_cert.bin`，也不要执行全片擦除。

将下方串口占位符替换成实际控制器端口：

```bash
esptool \
  --port /dev/cu.你的串口 \
  --baud 115200 \
  --before no-reset \
  --after hard-reset \
  --connect-attempts 0 \
  write-flash \
  0x1F2000 "/Users/apple/Desktop/cctcontroller/firmware/espressif/ESP ZeroCode_V4J7LD5NCCNYVB2BZXPAES_smart CCT controller2/Devices/1/fctry_cct_fixed_gpio4_cold_gpio5_warm.bin"
```

出现 `Connecting...` 后，按住 BOOT/GPIO9，再按一下复位，连接成功后松开 BOOT。等待写入及哈希校验成功；若未自动重启，释放 BOOT 后手动复位。

文件与分区均按 4 KB 对齐；该命令自动擦写 `0x1F2000–0x1F7FFF` 这 6 个扇区。

## 烧录后验收

先在面板开灯，将亮度设为 100%。每次调整后等待至少 2 秒，再观察：

| 面板操作 | 预期 |
|---|---|
| 最暖 | 暖白亮，冷白关断 |
| 最冷 | 冷白亮，暖白关断 |
| 中间色温 | 冷暖按比例混光 |
| 降低亮度 | 在当前混光比例下整体变暗 |
| 从最暖、最冷分别执行关灯 | 两路都关闭 |

如果结果仍不符合，下一步应读取完整启动日志或读回 fctry 分区，确认实际加载的是：

```json
{
  "pwm_hz": 4000,
  "temperature_mode": 1,
  "gpio_cold_or_cct": 4,
  "gpio_warm_or_brightness": 5
}
```

此前项目日志实测波特率为 74880，与烧录命令的 115200 是不同用途。必要时再比对 GPIO4/5 的实际 PWM 与灯带输出。

## 校验与边界

已校验全部 NVS 页头和条目 CRC、Blob 索引，以及 configuration 数据 CRC、JSON 字段和长度。相对初版 V4 仅 11 个字节改变：三个参数字节及两组四字节 CRC。详细结果见同目录 `Devices/1/fctry_cct_fixed_gpio4_cold_gpio5_warm.verification.json`，完整产品配置见同名 `.configuration.json`。

原文件自身存在 vendor-name 的长度/数据 CRC 不一致，已原样保留，未扩展本次修改范围；configuration 的 CRC 正常，未引入新的 NVS 校验异常。

本修正版的 Product Config 与既有 QD swap 相同，区别在于保留当前初版 V4 的其他设备数据；这个区别本身不能解释此前 QD swap 暖灯不亮。因此，本次完成的是与当前实测映射匹配的工厂配置修复，设备是否完全恢复须以上表实测为准。

主固件使用已核对的 Evaluation 文件（SHA-256 为 `e0e066937becaeb76d782060a4c709cadb2e89ee49a0ed20485d6e34f857f1bf`），其配置签名路径不进行签名验证；本说明不适用于未经核对的其他主固件。
